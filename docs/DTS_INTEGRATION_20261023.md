# DTS 整合记录（2026-10-23）

## 范围

现代 DTS 读取／解码整合入 `ttp_ac3dts.dll`。独立 `ttp_dts` 目录及其中构建产物保持原样，由用户处理；没有删除或改名该项目。当前发布聚合器原本就包含 `ttp_ac3dts`，继续使用该名称；未新增第二份 DTS 发行项。

## 保留与变更

- 原四工厂顺序 0 AC3 Decoder、1 DTS Decoder、2 AC3 Reader、3 DTS Reader 保持不变，类别 GUID、接口槽位与 `ttpGetSoundAddIn` 导出不变。保留历史显示名称，避免依赖工厂编号的旧宿主发生错位。
- AC3 保留 liba52 0.8.0、全局 IMDCT 一次初始化、原声道表和归一化。
- DTS Reader 与独立 Decoder 共用 `DtsCore`，静态链接 FFmpeg 9.0.2 DCA；删除 libdca 构建及原 DTS 通道复制表。
- 文件 Reader 直接输出 float64 或 PCM24，使用实际解码帧的声道掩码及采样率；保留旧宿主调用 ABI。
- 独立 Decoder 在收到数据前就协商输出格式，因此固定为 DTS Core，避免扩展层导致中途改变采样率／声道。它不冒充完整 DTS-HD Decoder。文件 Reader 则可在解码首帧后确定格式。
- 支持 16BE／16LE／14BE／14LE，处理跨输入块同步头、任意整帧输出容量、停止、EOF、重置及精确定位。
- 兼容旧 14 位传输中省略末尾填充字的文件，避免跨帧误吞下一个同步头。
- 修正固定帧长原始 DTS／DTS-WAV 时长：用实际压缩包帧数及每帧样本计算，避免按解包码率或外层 PCM 载体估算。读取 RIFF／RF64 的块头，支持大 JUNK 前缀，不扫描整首歌曲才能打开。
- 原始 DTS 标签、封面和可选宿主接口继续委托 `CreateStdContent`。Metadata／Thumbnail 保持 Reader 的 IUnknown 身份，保留最后释放时写入的生命周期。WAVE 元数据／封面只读。
- 原工厂 2 仍能像原版那样扫描到误后缀的压缩 DTS，并交给工厂 1 解码；推荐文件 DTS 走工厂 3。

## 音量与精度

原 QMF 除数 49152、LFE 除数 8388608 的证据见历史恢复文档。现代 DTS Core 主声道应用 `sqrt(2) * 32768 / 49152 = 0.9428090415820634`，LFE 保持原幅度；HD／无损配置不套用核心兼容衰减。

这是保留旧音量基准，不是重写 FFmpeg 滤波器。对本地双声道、低电平及 5.1 测试音，FFmpeg 与旧 libdca 仍有约 0.012 dB 主声道幅度差及滤波残差；不能声明原二进制 bit-exact。AC3 对照对象为整合前的重建 DLL，本轮输出逐字节一致；它与原始历史 DLL 的已有细微差异仍见历史文档。

## 验证

私有测试目录：`rebuild/tests/ac3dts_merge_20261023`。这些测试不提交、不进入发行包、不在 Action 中运行。

| 项目 | 结果／证据 |
| --- | --- |
| AC3 双声道、5.1 | 与整合前 DLL PCM 逐字节一致 |
| DTS 双声道、低电平、5.1、16LE、14BE | 文件 Reader 与独立 Decoder PCM 逐字节一致 |
| DTS-WAV 四种表示、大 JUNK 前缀 | 完整解码、声道掩码和定位通过 |

| 读错误、停止、重复 EOF、反向定位 | 返回错误／停止，EOF 无数据；定位输出与全解码相同位置一致 |

## 发行与体积

最终 DLL 为 **921,600 字节（900 KiB）**。整合前旧 AC3DTS 246,272 字节，独立 DTS 873,472 字节，两份合计 1,119,744 字节；统一后少 198,144 字节（约 17.7%），但单个 AC3DTS 比原来更大。

固定 a52dec／FFmpeg／GNU make 依赖构建时下载校验，完整对应源码另附；仓库保留许可证，DLL 不嵌入许可文本。运行 ZIP 仅有 `AddIn/ttp_ac3dts.dll` 和 `SHA256SUMS.txt`。现代 MSVC + VC-LTL／YY-Thunks，同一 x86/SSE2 DLL 兼容 XP SP3、Win7、新系统，不要求外置 FFmpeg 或 VC 运行库。

## 仍存在的边界

以下为 2026.10.23 首轮整合状态；第 3～5 项已由 2026.10.23p1 继续补全，详见 [后续实现与验收](BOUNDARIES_3_5_20261023.md)。

1. 原版 EXE 内置 WAVE Reader 可抢先接受 PCM 头 DTS-WAV。插件能正确解码，但无法保证原 EXE 对所有 `.wav` 都调用它；`.dtswav` 路径已验证，重建版按内容探测。
2. 缺少真实 DTS-HD MA／HRA／Express 样本。本轮接入相关后端，不将扩展层标记为实测通过；改名为 `.dtshd` 的 Core 样本不能替代 HD 验证。
3. 未新增 E-AC3 解码；AC3 范围不扩展。
4. 反向精确定位重放解码历史，长音频定位速度仍有优化空间。
5. WAVE 标签／封面目前不写入；原始流的持久化仍由宿主服务负责。本轮模拟服务验证委托与生命周期，不等同于所有历史标签格式的编辑验收。

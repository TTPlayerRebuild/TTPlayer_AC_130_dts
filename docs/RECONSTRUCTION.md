# AC3／DTS 恢复证据与边界

日期：2026-10-19。

原 DLL SHA-256：`5196ff7bb9cd3d29d789e71dd12c96c1fa41ac23436f694f1085167f90fca0a1`。

## 原版调用结构

- `60052cfe` 依次枚举四个工厂；Reader 类别 `476d15a5-d863-416a-8a59-a9c7d72ce04e`，Decoder 类别 `686d6670-fdaf-4fbd-a81a-fb05d6f9efb1`。
- `60051a78` 调用宿主 CreateStdContent、扫描同步头并扣除前缀、确定原始音频长度。
- `60051c5d` 返回压缩字节；`60051d6f` 按 `data_length * ms / duration` 定位，之后由 Decoder 重同步。
- `60052703/60052872` 输出 float64，默认通道数来自 Reader，输出块建议 1536 帧。
- `6005317b/600533df` 对解码器调整后的 level 做逆归一化，并按 `600612a8/600613b0` 的通道表交错输出。

## DTS 音量差异已修复

`60058f2d` 传给 QMF `60059952` 的常量 `6005f940` 为 **49152.0**；该函数实际以此为除数。LFE `600596fe` 的独立常量 `6005f948` 为 **8388608.0**。

libdca 0.0.7 在 `libdca/parse.c` 使用 `sqrt(2)*32768`，因此未经兼容补丁时，原版／新版主声道线性拟合为 `0.94280904153`；降低输入音量十倍仍完全一致。5.1 的五个主声道同此比率，LFE 则为 1。

构建时仅精确替换 QMF 常量为 49152，LFE 不变。补丁有固定字符串校验；上游源码改变时配置直接失败。修正后的双声道、低音量和 5.1 拟合均约 `0.99999999995`，最大残差 `1.2e-10`，属于浮点计算差异，不能声称逐字节完全相同。

## 其它修正

- 分片同步缓冲、7 字节短读、任意至少一帧的输出容量，不复制越界。
- 按原常量恢复通道顺序；DTS 原始位深从同步头读取，支持 16/20/24 位。
- 读取停止事件；无宿主通用标签服务仍能读取纯音频。保留有该服务时的宿主标签对象及保存生命周期。
- liba52 全局 IMDCT 表初始化只运行一次，避免并发扫描与播放发生数据竞争。
- 相比原版要求两个同长度同步帧，允许短文件中的一个完整有效帧；定位、断流与缓冲错误保留真实 HRESULT。

## 测试与未覆盖项

本地私有探针完整检查四工厂、波形格式、字节数、停止后重开定位及 canary。已实际测试双声道 AC3/DTS、5.1、DTS 16LE 和 14BE，与正常大缓冲输出一致。原版对照探针提供最小 CreateStdContent 宿主服务；它不是完整播放器 UI 测试。

AC3 新旧普通样本最大差异约 `3.48e-4`，5.1 最大差异约 `8.93e-6`；线性增益均约 1，LFE 一致。未把这部分标记为 bit-exact。E-AC3、DTS-HD 完整扩展层不是本插件原始支持范围；本实现采用对应核心格式，不声称加入这些新解码器。更多动态范围／DVD PES 和损坏流样本、实际宿主标签保存及旧系统运行以集成验证记录为准。

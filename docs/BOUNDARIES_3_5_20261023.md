# 第 3～5 项边界补全与独立 DTS 项目迁移

版本：2026.10.23p1。对应此前 `DTS_INTEGRATION_20261023.md` 的边界 3～5。

## 1. E-AC3

- 保留 0～3 号工厂及原 GUID，追加 4 号 `Dolby Digital Plus Reader`，支持 `.eac3`、`.ec3` 和误用 `.ac3` 后缀的 E-AC3。
- 使用固定 FFmpeg 9.0.2 的 E-AC3 decoder、AC3 parser 和原始流 demuxer。旧 AC3 Reader／liba52 Decoder 不替换，既有 AC3 输出回归保持逐字节一致。
- 输出 float64 或 PCM24，返回完整 WAVEFORMATEXTENSIBLE、采样率和声道掩码；新增 Probe／SourceInfo，不将 E-AC3 谎报为旧 AC3。
- 重建播放器补齐文件筛选／缓存扩展名。原版 5.7.9 无需理解新 Probe 接口，仍可枚举追加的 Reader。
- 这是 E-AC3 文件解码，不包含 Atmos 对象渲染、设备直通或任意视频容器的音轨解封装。

## 2. 有条件的准确快速定位

稀疏索引在顺序解码时建立，每约 1 秒记录一个独立 DTS Core 帧的绝对样本位置和字节位置。最多 65,536 项，达到上限后减半并增加采样间隔，避免长文件无限占用内存。

独立性依据帧头的 `predictor_history`，以及首个子帧各子带的 prediction mode。部分编码器虽然设置历史标记，但首个子帧完全不用预测；这类帧也能安全覆盖 ADPCM 历史。只解析有界侧信息，畸形或不确定的帧不建快速定位点。

反向定位选择目标前至少 2 秒的索引点，重新建立解码器，从该点预卷并丢弃到目标样本；核对 demuxer 返回的首包字节位置。普通 DTS Core 的滤波历史由预卷恢复。ES、96/24、HD，以及 E-AC3 等未证明可重置的状态继续从头解码，不以速度换取未经验证的音频结果。

120 秒、768 kbit/s 测试文件定位至 90 秒或 60 秒，输入读取均为 **294,912 字节**，不再读取从文件头到目标的数 MB 数据。裸 DTS、WAVE 包装、14 位 BE、16 位 LE、5.1 样本的定位结果与顺序解码对应位置逐字节一致。

## 3. WAVE 标签和封面写入

新增原生 RIFF／RF64／BW64 编辑器：

- 标准文本、Unicode、自定义 TXXX、COMM／USLT、PNG／JPEG／WebP APIC；支持多封面、图片类型、描述及 ReplacePicture 字段掩码。
- 保存到容器内的 `id3 ` 块，保留现有 ID3v2.3／v2.4 版本。更新或删除字段时同时移除相应旧 LIST/INFO 值，防止删除后又读取到旧值。
- 复制 fmt、data、未知块、未知 INFO 条目与未修改的 ID3 帧，更新 RIFF 总长度或 ds64 的总长度。音频载荷不重新编码。
- 只写宿主提供的可写 IStream。只读检查可以报告文件的可编辑能力，但实际 Set／写入必须取得可写流；不凭 Stat 显示名称重新打开路径。
- 有界块扫描、64 MiB 标签上限、每张封面 16 MiB／最多 32 张。临时磁盘文件保存完整旧内容和新内容，音频复制使用 64 KiB 缓冲，不把整首音频放入内存。
- 写入、截断或 Commit 失败时尝试恢复旧内容；若底层介质持续失败导致恢复也失败，保留 `%TEMP%` 中的 `tda*.tmp` 恢复副本，通过调试输出报告路径并返回失败。该方案不保证突然断电或磁盘物理故障下的原子替换。
- 可选 MetadataCommit 为终结操作：关闭解码后只尝试保存一次，重复提交返回同一结果，最终 Release 不重试显式失败。原版宿主不调用此接口时，在最后释放 Reader 及其关联接口后保存。

为保护原数据，带全局 unsynchronisation／扩展头、多个 ID3 块、复杂 ds64 大块表等尚未实现可靠保留的结构，仍可尝试播放和读取，但不开放原生写入。不是所有 RIFF 变体都宣称已可编辑。

## 4. 裸 DTS 的真实宿主服务

仍委托 `CreateStdContent`，并修正旧说明中的笼统生命周期描述：

- 原版 5.7.9：实测 Unicode 文本保存、重新打开和删除通过；其 Thumbnail MaximumCount 为 0，AddPicture 返回 E_NOTIMPL，因此不能声称原版公共服务支持写入裸 DTS 封面。
- 重建版：使用实际 `CreateStandardContent` 实现，文本和 APE 封面保存、重读、删除通过。其 Set 会即时保存，并非统一延迟到最终 Release。
- 插件按宿主报告的 MaximumCount 决定封面能力，不伪造写入成功。WAVE 的原生封面写入不受上述旧宿主服务限制。

混合 ID3／APE 样本还发现重建宿主删除后回退到旧 ID3 值的问题。已修正 `rebuild/src/audio/builtin_file_info.cpp`：删除字段或封面时清除低优先级 ID3 的相应内容，保持前置标签原长度、音频字节和已有读取偏移；保留未改动帧及未知二进制。另修正 ID3v1 位于 APE 之前时的真实偏移记录。ID3v1、ID3v2、APE、两种混合排列均完成保存／删除／重读验证，音频载荷不变。

## 5. XP 加载／退出问题

新增实际宿主标签测试发现：只链接 YY-Thunks 对象但不设置 DLL 初始化入口，可能在 XP 的 LoadLibrary 路径下把 VC-LTL 的线程局部存储映射到宿主空间，最终在宿主 TLS 析构时访问冲突。

按所用 YY-Thunks 1.2.2 的 Readme §2.4.1，DLL 增加：

```text
/ENTRY:DllMainCRTStartupForYY_Thunks
/alternatename:_YY_ThunksOriginalDllMainCRTStartup@12=__DllMainCRTStartup@12
```

复测同一 XP 用例完成后正常退出 0。静态导入审计不能代替这个运行检查。未修改其它插件的构建；后续新 DLL 应遵守此入口要求。

## 6. 验收和迁移对应关系

私有测试在 `rebuild/tests/ac3dts_complete_20261023`，不上传、不在 Action 运行、不进入发行 ZIP。

| 原独立 ttp_dts 功能 | 迁移位置与验收 |
| --- | --- |
| DTS／DTS-WAV、大小端、14／16 位、前置 JUNK | 3 号 Reader；旧格式矩阵与大块测试 |
| DTS-HD 后端 | 相同 FFmpeg DCA 后端保留；真实 MA／HRA／Express 样本仍待验收 |
| float64／PCM24、EXTENSIBLE／声道掩码 | dts_core／dts_reader；旧 Reader／Decoder PCM 一致性 |
| IStream、短读、错误、Stop、EOF、容量 | 原 31 项回归；缓冲哨兵与非定位流 |
| 精确 Seek | 保留从头回退，新增独立 Core 稀疏索引 |
| Probe／SourceInfo | 保留协议 ABI 和容器／编码分离，追加 E-AC3 |
| 元数据／封面读取 | 全部保留，新增 WAVE 写入及真实宿主委托验收 |
| 日期版本、静态后端、XP／Win7、源码包、许可证 | 统一到 ttp_ac3dts 的构建和发行 |

本地已验证 31 项原回归、40 项 RIFF/RF64 与 ID3v2.3/v2.4 编辑／故障恢复检查；XP SP3、Win7 SP1 执行解码、准确定位、WAVE 保存和重新读取。六声道 E-AC3 的 Win11／XP／Win7 PCM SHA-256 相同。原版与重建播放器在三个系统中均验证插件加载、推进播放和正常关闭；Windows 10 按用户要求由 Win11 代验，未称为独立 Win10 实测。

独立 `ttp_dts` 没有需要继续保留的独有实现。确认迁移后，将本地项目和 Release 中的独立 DLL／运行 ZIP／源码 ZIP 移入私有测试目录的 `retired` 子目录，同时保留逐文件 SHA-256 验证的 ZIP 备份。完整目录包含 `.git`、已暂存／未提交文档与构建文件；采用可恢复归档，工作区根目录不再保留 `ttp_dts`。没有删除远端 Git 仓库或远端 release。当前打包入口只分发 `ttp_ac3dts`。

仍保留原边界 1、2：原版 EXE 的内置 WAVE Reader 优先接收普通 `.wav`，以及缺少真实 DTS-HD 扩展层样本。原版使用 `.dtswav` 路径；重建版按内容路由。
